# 团队贡献与准入规范

本文件用于框架维护者和业务测试贡献者。团队模式与发布职责见 `ENTERPRISE-TEAM-MODE.md`；CI 接入见 `ci/README.md`。

模块、Java、用例、配置和资源命名遵循 [工程规范](docs/ENGINEERING-STANDARDS.md)。完整流程与失败边界见 [闭环审计](docs/LIFECYCLE-AUDIT.md)，不要把示例名、旧兼容入口或未验证的规划能力复制为新标准。

## 修改边界

业务域维护业务用例、数据工厂和断言；公共核心只放跨域复用的契约和生命周期能力。Dubbo、Kafka、XXL-JOB 或公司网关适配放入适配器，不能让纯 HTTP 消费方被迫引入所有中间件。

新增代码优先使用实例专属 RuntimeProvider、显式客户端配置和 AutoCloseable。并行测试不修改全局 RuntimeRegistry，也不在执行期间改 JVM 系统属性。声明线程归属和关闭行为，明确超时后远端操作是否可能已经发生。

每项可进入长期回归的业务用例要有稳定逻辑 ID、所属团队/业务域、维护者、测试层级、风险等级和环境边界。当前分片按方法逻辑ID，一个DataProvider方法的全部数据行同属一分片；数据行仍需要稳定ID，不能按运行顺序、随机 UUID 或当前线程选择分片。报告的运行 caseId 可每次不同，不能拿它当历史用例主键。

## 提交前验证

1. 阅读改动目录的规范，保留他人的未提交文件。只改本任务范围。
2. 修改Java后先运行 `mvn spotless:apply`，在框架目录运行 `./verify-lifecycle.ps1` 完成全量闭环验收；聚焦开发测试可直接使用Maven，但部分集合不作为完整验收。旧 `verify-framework.ps1 -ReportOnly` 仅用于已有模块报告检查，不应再次clean清除证据。
3. 生命周期、并发、超时、资源租约等公共能力需要验证失败路径；协议适配需要保留可回放的本地契约测试。业务用例按场景验证，不写只重复实现的测试。
4. 外部联调单独运行明确选择的 profile，使用批准的专用测试资源，并记录副作用和清理结果。未执行真实平台验收时写明，不能以 MockConsumer 等替身报告代替真实平台证据。
5. 修改公共 API、默认值或配置键时，更新变更记录、迁移说明、样例与能力文档；增加配置不能破坏只启用一项能力的消费项目。

## Review 与合并

公共 API、运行时、认证、环境准入或资源隔离修改至少由相应维护者审查；配置/CI/发布路径还需平台或安全负责人参与。具体账号由公司维护，`ci/CODEOWNERS.example` 不会自动执行任何权限策略。

PR 应说明问题、最终行为、测试证据和实际边界。合并要求 CI 成功、无未解决评审、无真实凭据，并且公共契约迁移说明齐全。失败用例禁止为了过门禁直接删除、全跳过或自动重试掩盖；有隔离需求时记录责任人、缺陷链接和到期时间，隔离用例不计入发布成功覆盖。

依赖版本由父 POM/BOM 统一管理。新增依赖检查许可证、公司漏洞扫描结果和必要性；插件版本也要固定。公共库不要引入业务服务的秘密配置或隐式连接生产环境。

## 数据与凭据

造数成功后立即登记补偿清理，以本次 namespace/runId 限定删除范围。事务回滚不能回滚被测远程服务的提交。租约被中断/过期后应检查资源是否恢复可用，不将本地 JVM 锁当作分布式锁。

凭据由公司密钥服务或 CI 凭据注入。环境变量并不自动保证保密：不要打印完整变量、参数、响应、Cookie 或 JDBC URL 中的密码；报告和错误文本也要检查。

## 缺陷与支持

问题记录至少包括框架/BOM版本、Git SHA、JDK、操作系统、环境、稳定用例 ID、runId、脱敏失败栈、复现步骤和副作用/清理状态。由业务域先确认被测服务问题，公共生命周期或协议问题交框架维护者；支持响应目标由团队协议确定。
