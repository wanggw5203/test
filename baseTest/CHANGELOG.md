# 变更记录

## 1.1.0-SNAPSHOT — 企业团队模式（未发布）

目标是支持约100人的多团队协作，具体能力和验收边界见 `ENTERPRISE-TEAM-MODE.md`。这些工作仍在当前开发版本中，不代表已向私有仓库发布新版本。

- 统一父 POM 与 BOM，集中治理 JDK、插件、框架和适配器版本。
- 增加企业接入样例及团队运行的准入、标识、分片、namespace、资源租约扩展入口。
- 增加只检查既有报告的 CI 门禁入口，避免门禁阶段重复执行构建。
- 增加HTTP origin准入、JDBC资源租约与可重算的分片计划清单；全分片脚本阻断遗漏、漂移、失败和截断报告。
- 提供 Jenkins、本地代码所有者示例、贡献规范和团队验收文档。
- 2026-10-15闭环审计：修复配置阶段运行时、报告/清理错误传播、Kafka失败/提交未知、XXL-JOB未知触发结果、JDBC初始化释放和任务关闭终态。
- 新增规范注解 `@TestCaseMetadata` 及 `XxlJobDialect.forVersion()`，旧入口保留弃用兼容；团队示例按业务行为命名，稳定用例ID不变。
- 增加Spotless格式门禁、CycloneDX含测试依赖的SBOM、统一生命周期验收入口及源码/报告/制品证据复验。
- 按上游公告将Jackson调整至维护版本2.18.11、Kafka客户端调整至3.9.2，完整回归结果见当前验收记录。
- 对传递依赖统一Netty BOM4.2.19.Final与LZ4 Java1.12.0，补依赖审查记录；不将公开记录匹配快照等同于公司扫描认证。
- 增加闭环审计、命名与兼容规范、前沿技术优先级和验收条件文档。

正式发布前必须补全最终测试结果、破坏性变更、迁移说明和制品坐标；不将计划项或未通过验证的能力写进发布承诺。

## 1.0.0 — 上一轮本地开发基线

该版本号用于本地构建/安装，当前未确认存在远程仓库正式发布记录。不要反复覆盖公司仓库中的同名 release。

- TestNG 数据驱动、JSON 断言、身份及运行时作用域、生命周期清理与 JSONL 报告。
- HTTP、SDK、Dubbo、Kafka、XXL-JOB、JDBC 与本地 Mock/任务能力。
- local/dev/qa 配置、配置失败报告、SDK 关闭取消、任务终态等待和 JSON 契约断言。
- 上一轮记录的默认本地回归为73条顶层测试；最新构建结果以当前 Surefire 报告和验收记录为准。

## 后续版本规则

兼容修复使用 patch；增加兼容 API 使用 minor；删除/更改公共契约、默认行为或配置语义使用 major。未发布开发版使用 `-SNAPSHOT` 或公司批准的预发布标识。依赖 BOM 固定精确版本，不使用动态范围、LATEST 或自动解析最新版本。

适配器版本兼容范围需有契约和真实环境证据。框架 release、BOM、父 POM 应保存关联版本和 Git SHA；生产消费团队可以独立升级，不强制所有业务库同时跟随主分支。
